# Android native build — required fixes

`mobile/android/` is generated by `expo prebuild` and is **gitignored**. Every
fix below lives in that folder, so **`expo prebuild --clean` wipes all of them**
and the build breaks again exactly as described. Re-apply this file afterwards.

---

## 1. Gradle must run on JDK 21, not 25

**Symptom**

```
:expo-modules-core:configureCMakeDebug[arm64-v8a]   1 error
:expo-modules-core:configureCMakeDebug[armeabi-v7a] 1 error
:expo-modules-core:configureCMakeDebug[x86]         1 error
:expo-modules-core:configureCMakeDebug[x86_64]      1 error
WARNING: A restricted method in java.lang.System has been called
```

**Cause.** `expo prebuild` writes `gradle/gradle-daemon-jvm.properties` with
`toolchainVersion=25`. Under JDK 25 the Prefab CLI
(`com.google.prefab:cli`, which resolves native dependencies out of AARs)
calls `System.load` through JNA. JDK 25 restricts that method and prints a
warning to **stderr** — and the Android Gradle Plugin treats *any* prefab
stderr as a task failure. The "1 error" on each ABI is nothing but that
warning text.

Confirmed by reading
`node_modules/expo-modules-core/android/build/intermediates/cxx/Debug/*/logs/*/prefab_stderr.txt`,
which contains only warnings, and by running the prefab jar under JDK 21,
which emits nothing at all.

**Fix**

1. Install JDK 21 (Temurin) — currently at `D:\Android\jdk\jdk-21.0.12.1+1`
2. **Delete** `mobile/android/gradle/gradle-daemon-jvm.properties`.
   Do not merely change `toolchainVersion` to 21: that file exists for
   auto-provisioning, and without its `toolchainUrl` entries Gradle fails with
   *"Unable to download toolchain matching the requirements"*. Deleting it
   reverts to `org.gradle.java.home`.
3. Append to `mobile/android/gradle.properties`:

```properties
org.gradle.java.home=D:\\Android\\jdk\\jdk-21.0.12.1+1
org.gradle.java.installations.paths=D:\\Android\\jdk\\jdk-21.0.12.1+1
org.gradle.java.installations.auto-download=false
```

4. In Android Studio: **Settings → Build, Execution, Deployment → Build Tools
   → Gradle → Gradle JDK** → point at the same path. Studio's setting
   overrides `gradle.properties`.

## 2. NDK and CMake must be installed

`expo-modules-core` compiles C++. The Android Studio "Custom" setup wizard
installs neither by default.

The exact versions are not in any gradle file — read them from Gradle's own
`node_modules/expo-modules-core/android/.cxx/Debug/*/arm64-v8a/metadata_generation_command.txt`:

```
-DANDROID_NDK=D:\Android\Sdk\ndk\27.1.12297006
-DCMAKE_MAKE_PROGRAM=D:\Android\Sdk\cmake\3.22.1\bin\ninja.exe
```

```bash
D:\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat --sdk_root=D:\Android\Sdk "ndk;27.1.12297006" "cmake;3.22.1"
```

## 3. Build from Android Studio, never `gradlew`

From a Claude tool shell every Gradle build fails with
`java.io.IOException: Unable to establish loopback connection`; the daemon
side reports `SocketException: Invalid argument: connect`.

Ruled out by testing: java resolves `localhost` to both 127.0.0.1 and ::1 and
cross-process connects fine, only Windows Defender is installed, no firewall
rule touches java, `gradlew --version` works, `preferIPv4Stack` does not help,
and it reproduces writing to a file so it is not a truncated pipe.

Android Studio's daemon connects immediately. The agent shell has a non-stock
environment (`NoDefaultCurrentDirectoryInExePath=1`) which the daemon
inherits. **Claude writes and typechecks the code; a human presses Build.**

## 4. Emulator must be arm64, and resized

The default Pixel AVD is x86_64 and **cannot load the model** — `loadModel`
crashes silently. Everything else in the app runs fine on it, so the failure
is easy to misread.

`anupalan_pixel7pro` is created with `system-images;android-35;google_apis;arm64-v8a`
and `D:\Android\avd\anupalan_pixel7pro.avd\config.ini` edited from the
defaults, which cannot hold Gemma 4 E4B:

| setting | default | set to | why |
|---|---|---|---|
| `hw.ramSize` | 1536M | **6144M** | 3.3 GB of weights on the CPU path |
| `disk.dataPartition.size` | 800M | **14G** | the model file alone is 3.66 GB |
| `vm.heapSize` | 384M | **1024M** | |

The GPU backend is unavailable in an emulator regardless of image, so expect
the CPU path at roughly 2–4 tok/s under binary translation. A physical
Android device runs the same APK and the same `.litertlm` file at ~22 tok/s
with no code changes.

---

## Order of operations after a fresh `expo prebuild`

1. Delete `gradle/gradle-daemon-jvm.properties`
2. Add the three `org.gradle.java.*` lines to `gradle.properties`
3. Set Gradle JDK to 21 in Android Studio
4. Sync, then **Build → Make Project**
